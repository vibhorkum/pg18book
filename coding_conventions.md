# Coding Conventions
Last udapted: July 20, 2025


## Identifiers
All identifiers are lower case. Avoid quoted identifiers and spaces in identifiers. All names start with a character of the alphabet or a number.
Maximum length for an identifier is 63 characters. Click here for the complete  definition of [PostgreSQL identifiers](https://www.postgresql.org/docs/current/sql-syntax-lexical.html#SQL-SYNTAX-IDENTIFIERS).

Complex identifiers use snake_case.
This is true for databases, schemas, tables, views, columns, constraints, indexes, functions, procedures,  variables, ...

For example:
```sql
product_price
```

## Naming conventions

Table names are singluar, for example: _product_ instead of _product**s**_

**Column names** should be meanginul and avoid abbreviations. for example _description_ and not _desc_.

**Primary keya**, especially synthetic keys that are used as primary keys, are called _id_ (preferred) or _<table_name>.id_

**Foreign key references** should combine the table name and the column name using snake case notation. For example _product_id_ referes to the column _id_ in the table _product_.
In the definition for the table _product_price_ this could be used as follows

```sql
CREATE TABLE product_price 
(
    ...,

    product_id REFERENCES product (id),

    ...
)
```

**Function names** start with _sf__, except for the create/update/delete functions defined as part of the API schema (see below).

**Procedure names** start with _sp__

**Temporary table names** start with __temp_

**View names** start with __vw_

**Materialized view names** start with __mv_

**PostgreSQL key words** are always capitalized, for example
```sql
SELECT id, description 
    FROM product_reference.product 
    WHERE description ILIKE '%jeans%'
    ORDER BY description ASC;

```


## Databases and schemas
Databases should have meaningful names that are associated with the business purpose, for example _hr_ or _ecommerce_.
Schemas should be used to manage related concepts inside a single name space. 

For example
``` sql
CREATE SCHEMA product_reference;

CREATE TABLE product_reference.product_category (...);
CREATE TABLE product_reference.product_brand ();
...

CREATE SCHEMA sales;

CREATE TABLE sales.order(...);
CREATE TABLE sales.order_lines(...);
...
```
The _public_ schema will not be used and should be dropped to avoid any confusion and disallow any implict access.

## Procedures and functions

Function and procedure definitions use named parameters. Use of positional parameters references should be avoided.

**Parameter names** are prefixed with __p_;

**Internal variable names** are prefixed with __v_;

For example

```sql
CREATE PROCEDURE product.sp_calculate_price (p_id INTEGER) AS
$$
DECLARE
    v_new_price NUMERIC;
    ...
BEGIN
...
$$ LANGUAGE PLPGSQL
```

## API schema 

Databases expose an **api schema** that contains the application interface to the database.
By default, the API exposes create/read/update/delete functionality. Application calls should be limited to the functionality exposed by the API schema. This can be enforced though security and visibility restrictions.

**Create** is implemented through the _add__<table_name> function. Unless provided, the primary key will be autogenerated. Values for all columns have to be provided.
_create_<table_name>_ will return the new record if the update is successful, _NULL_ otherwise. 

**Update** is implemented through the _update__<table_name> function. Only the values for columns to be updated have to be provided; other columns can have NULL values and will remain unchanged.
_update_<table_name>_ will return the new record, and the old record if the update is successful, _NULL_ otherwise. 

**Delete** is implemented through the _delete__<table_name> function. Only the primary key is to be provided.
_delete__<table_name>_ will return the deleted record, _NULL_ otherwise. 

**Read** is implemented through the _<table_name>__vw_ view (or _<table_name>__mv_ for a materialized view)

## Comments

**Single line comments** are limited to 80 characters and can use the '---' to indicate a comment line

**Multi-line comments** use the /* ... */ convention. Individual lines are limited to maximum 80 characters.

Examples

```sql
--- This is a single line comment. The line is less than 80 characters long

/* 
=================================================================
This schema define the product reference data. The tables are:
- product_category, e.g., pants, shirts, polos, sweaters
- product brand, e.g., Boss, Levis, The Gap, ...
- product, e.g., a blue shirt from Boss
- product prices with information about currency, geography and date range 
  when the pice was applicable
-- =================================================================
*/

```
